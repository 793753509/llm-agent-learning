# Day 05：从“查自习室几点关门”开始学 RAG

> 今天先学会一件事：让程序找到一小段资料，再让模型根据这段资料回答。

这节课从一个完整例子开始。你只需要认识字符串、列表、字典、循环和函数；遇到新的写法，下面会解释。

第一次读第 1～3 节，能说清楚“谁查资料、谁写答案”就可以。第二次对着代码读第 4～9 节，最后做第 10 节的三个小练习。扩展内容可以留到以后，不必一天全部学完。

## 1. 先想一个具体问题

假设你要给一家**虚构的“青禾自习室”**做问答助手。我们在电脑上写了一份资料：

```text
周末开放时间为 09:00—18:00，18:00 关门。
```

现在有人问：

```text
周末几点关门？
```

答案在文件里，但模型不会因为你电脑上有这个文件，就自动知道它写了什么。

你在 Day 04 已经见过类似的事情：计算器在 Python 中算出 `75` 后，还要把结果放进下一次模型请求，模型才能使用它。这里也一样：**程序读到了资料，还得把资料发给模型。**

我们可以这样做：

1. Python 读取自习室资料。
2. Python 找到关于“周末关门”的段落。
3. Python 把“问题 + 这段资料”一起发给模型。
4. 模型根据资料组织回答，并写明来源。

这就是今天要实现的 RAG。英文全称是 Retrieval-Augmented Generation，中文通常叫“检索增强生成”。先把这三个词翻译成动作：

| 名字 | 实际动作 | 本例中发生什么 |
| --- | --- | --- |
| Retrieve，检索 | 找资料 | 找到“周末 18:00 关门”这一段 |
| Augment，增强 | 在模型输入里补充资料 | 把这一段和用户问题放在一起 |
| Generate，生成 | 模型写回答 | “周末 18:00 关门。[来源: hours.md#1]” |

你可以把它想成开卷答题：先翻到相关的一页，再根据那一页作答。本课代码不会训练模型或修改模型参数；资料通过本次请求交给模型使用。

**先停一下：是谁打开电脑里的文件？**

答案是你的 Python 程序。模型在最后一步才收到我们选出来的文字。

## 2. 先不看代码，手动走完一次

假设资料里有四个小段落：

| 编号 | 段落中的主要内容 |
| --- | --- |
| `hours.md#1` | 周末 09:00—18:00，18:00 关门 |
| `hours.md#2` | 周一至周五 08:00—21:00，21:00 关门 |
| `services.md#1` | 座位需要提前一天预约 |
| `services.md#2` | wifi 免费，连接方式请咨询前台 |

用户问“周末几点关门？”。你会选择第一段，因为它同时提到了“周末”和“关门”。

我们让程序也做这种简单比较：看问题中的哪些词或字，在段落里出现过。然后只把得分最高的一段放进模型输入：

```text
问题：周末几点关门？

参考资料开始：
[来源: hours.md#1]
## 周末开放时间
周末开放时间为 09:00—18:00，18:00 关门。
参考资料结束。
```

另外告诉模型：“只根据资料回答，资料没写就说无法确定，回答要带来源。”

合理的回答应该类似这样，具体措辞可能变化：

```text
周末 18:00 关门。[来源: hours.md#1]
```

注意这条来源链：

```text
hours.md 文件
    ↓ Python 读取、分段
hours.md#1：包含周末开放时间的一小段文字
    ↓ Python 按问题挑选
问题 + 这段原文 + 来源编号
    ↓ 发送给模型
回答 + [来源: hours.md#1]
```

`18:00` 来自原始资料；`hours.md#1` 是程序给这段资料的编号；模型负责把资料组织成对用户问题的回答。

## 4. 第一步：读取文件，把内容放进变量

“加载文档”听起来复杂，核心就是把文件内容读成 Python 字符串。

下面是**可以单独运行的离线小实验**，在项目根目录运行：

```python
from pathlib import Path

path = Path("day05/knowledge/hours.md")
text = path.read_text(encoding="utf-8")
print(text)
```

`path` 指向开放时间文件，`text` 保存文件里的文字。`encoding="utf-8"` 指定读取文字时使用的编码。

完整示例中的 `load_documents()` 会读取两个文件，返回一个字典：

```python
# 结构示意：省略号表示这里没展示完整文字。
documents = {
    "hours.md": "## 周末开放时间\n周末开放时间为……",
    "services.md": "## 预约\n座位需要提前一天预约……",
}
```

字典的键是文件名，值是这个文件的全部文字。

此时发生的事情只有“硬盘上的文字 → Python 变量”，还没有检索，也没有请求模型。不要把 `print(text)` 理解成“把资料发给模型”；它只是打印给你看。

完整加载函数还会跳过隐藏文件、子目录、符号链接和不支持的后缀，忽略空文件，并报告过大文件或编码错误。第一遍先理解返回的字典即可。

## 5. 第二步：把长资料拆成小段，也就是 chunk

### 为什么要拆？

今天只有四小段，你把全文发给模型也能完成这个问题。假如以后有几百份文件，每次都发全文会增加请求长度，也会带入大量不相关内容。

所以我们先把资料拆成能单独搜索的小段；用户问什么，就挑选相关的小段。

**chunk 就是一小块文本。** 它是普通数据，不是某种模型能力。

本课按空行分段。例如文件中的这两段：

```markdown
## 周末开放时间
周末开放时间为 09:00—18:00，18:00 关门。

## 工作日开放时间
周一至周五开放时间为 08:00—21:00，21:00 关门。
```

中间有一个空行，所以会变成两个 chunk。标题和正文之间没有空行，会留在同一块里。

这是我们为小例子选的规则，不是所有文档都应该按空行切；长文档还需要处理超长段落、标题和上下文。

### 一块资料保存什么？

代码用一个 `dataclass` 把相关数据放在一起：

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class Chunk:
    id: str
    source: str
    index: int
    text: str
```

`str` 表示字符串，`int` 表示整数；`frozen=True` 表示创建后不能直接重新赋值这些字段。

第一块数据相当于：

```python
chunk = Chunk(
    id="hours.md#1",
    source="hours.md",
    index=1,
    text="## 周末开放时间\n周末开放时间为 09:00—18:00，18:00 关门。",
)
```

- `chunk.text`：原文，模型最后要读的内容。
- `chunk.source`：来自哪个文件，方便回去核对。
- `chunk.index`：在这个文件里排第几块，从 1 开始。
- `chunk.id`：文件名和序号组成的完整编号，用于引用。

`#1` 是我们自己规定的编号格式，不是 Markdown 的行号，也不是模型生成的编号。相同文件重复切分会得到相同编号；在前面插入新段落后，后面编号会改变，所以这还不是跨文档版本的永久标识。

`split_documents()` 最终返回 `list[Chunk]`，也就是“装着多个 Chunk 的列表”。

### “索引”又是什么？

你可能见过“加载 → 切块 → 建索引 → 检索”的说法。建索引是把资料组织成便于搜索的形式。

今天直接把全部 chunk 放在内存列表里，每次逐个比较，没有单独建立搜索索引或向量数据库。这样足够演示小知识库；资料多了，再学习如何加速搜索。

## 6. 第三步：程序怎么判断哪段比较相关？

### 6.1 先做最容易看懂的比较

我们写一个很简单的规则：

> 问题里出现的词或字，在这段资料里也出现得越多，就给这段越高的分数。

这是本课的“关键词检索基线”：先做一个简单、能解释结果的版本，留作以后改进时的比较对象。

为了方便演示，英文按连续单词拆，中文按一个个汉字拆，标点不参与比较。下面是完整示例里的拆分函数：

```python
import re

TOKEN_PATTERN = re.compile(r"[A-Za-z0-9_]+|[\u4e00-\u9fff]")


def tokenize(text: str) -> set[str]:
    tokens = TOKEN_PATTERN.findall(text)
    return {token.lower() for token in tokens}
```

第一遍不用背正则表达式。你只需要看懂这个函数的输入和输出：

```python
tokenize("周末几点关门？")
# 得到这些元素：{"周", "末", "几", "点", "关", "门"}

tokenize("WiFi wifi")
# {"wifi"}
```

`lower()` 把英文字母转成小写；`set` 是集合，会去掉重复元素，元素顺序不固定。所以两个 `wifi` 只算一个。这里叫 token 的词或字是我们自己拆出来的检索单位，**不等于模型 API 计费使用的 Token**。

### 6.2 手算第一段的分数

问题拆出来的集合有 6 个元素：

```text
周、末、几、点、关、门
```

第一段资料里能找到其中 4 个：

```text
周、末、关、门
```

本课约定：

```text
分数 = 共同元素的数量 ÷ 问题中不重复元素的数量
     = 4 ÷ 6
     ≈ 0.667
```

第二段也有“周一至周五”和“关门”，所以命中了“周、关、门”，得到 `3 ÷ 6 = 0.500`。它的分数比周末段落低，但并不是零。

预约和网络两段没有这些字，因此都是零分。

### 6.3 把手算写成 Python

以下是 `score()` 的源码节选；`tokenize()` 和 `Chunk` 已在完整文件中定义：

```python
def score(query: str, chunk: Chunk) -> float:
    query_tokens = tokenize(query)
    if not query_tokens:
        return 0.0
    chunk_tokens = tokenize(chunk.text)
    overlap = query_tokens & chunk_tokens
    return len(overlap) / len(query_tokens)
```

逐行理解：

1. `query` 就是用户问题，不是新的对象类型。
2. `query_tokens` 保存问题拆出来的集合。
3. 空集合直接返回零，避免后面除以零。
4. `chunk_tokens` 保存资料拆出来的集合。
5. `&` 在两个集合之间表示“交集”，取两边都有的元素。
6. `len()` 数元素个数，相除后得到分数。

`0.667` 只是这条规则算出的字面匹配分数，**不是答案有 66.7% 的概率正确**。这个方法也不真正理解意思：长段落可能因为碰巧含有很多字得到高分，同义词则可能完全匹配不到。

## 7. top-k：排好序以后，最多拿几段？

`top` 表示排名靠前，`k` 表示数量。`top_k=1` 就是最多取排名第一的一段。

在本例中：

| 设置 | 选中的资料 |
| --- | --- |
| `top_k=1` | 周末开放时间 |
| `top_k=2` | 周末开放时间、工作日开放时间 |
| `top_k=5` | 仍然只有上面两段，因为本课会先丢掉零分段落 |

`retrieve()` 做三件事：逐段打分、按分数从高到低排序、取前 k 个。源码里的：

```python
results.sort(key=get_score, reverse=True)
return results[:top_k]
```

`key=get_score` 告诉排序函数看每个结果的分数字段；`reverse=True` 表示高分在前。`[:top_k]` 是列表切片，表示取最前面的至多 k 项。同分时保留原来的先后顺序。

每个结果包含两部分：

```python
@dataclass(frozen=True)
class SearchResult:
    chunk: Chunk
    score: float
```

`result.chunk.text` 是原文，`result.score` 是分数。必须保留原文，后面模型才能读它；只把 `0.667` 发给模型，模型无法从中知道关门时间。

试一下这个本地命令：

```bash
uv run python -m day05.rag_baseline "周末几点关门？" --top-k 2
```

观察第 4 步的 `input`，现在应该有两个来源。k 增大后提供的文字通常更多，也可能带入不相关资料；在这道问题里，工作日开放时间不是必需信息。

## 8. 第四、五步：把资料放进请求，再生成回答

### 8.1 增强输入：实际就是拼接字符串

Prompt 在这里指给模型看的提示内容。`build_prompt()` 将“问题、选中的原文、来源编号”拼在一起：

```python
def build_prompt(query: str, results: list[SearchResult]) -> str:
    blocks = []
    for result in results:
        chunk = result.chunk
        blocks.append(f"[来源: {chunk.id}]\n{chunk.text}")
    evidence = "\n\n".join(blocks)
    return f"问题：{query}\n\n参考资料开始：\n{evidence}\n参考资料结束。"
```

`f"...{变量}..."` 会把变量值放进字符串；`\n` 表示换行；`"\n\n".join(blocks)` 用空行把多段资料连接起来。

只把 `results` 中选中的段落放进来，没有把全部知识库都发出去。第 2 节展示的那份输入，就是这个函数产生的。

### 8.2 生成：熟悉的模型调用

`generate_answer()` 中的核心请求沿用前几天的调用方式：

```python
# 源码节选：client、MODEL、INSTRUCTIONS 都已在完整示例中准备好。
response = client.responses.create(
    model=MODEL,
    instructions=INSTRUCTIONS,
    input=prompt,
)
return response.output_text
```

- `instructions` 放回答规则：根据资料回答、证据不足就说无法确定、标注来源。
- `input` 放本次问题和检索出的原文。
- `response.output_text` 是模型生成的文字。

打印 `prompt` 是让我们检查输入；传给 `input=prompt` 才是让模型实际收到它。

本课没有让模型决定何时调用搜索工具，检索由 Python 按固定流程执行，因此不需要 Day 04 那样的工具循环。以后可以把检索包装成工具交给 Agent 使用。

### 8.3 两种“没有答案”，要分开看

**情况一：检索一个结果也没找到。**

例如使用本课资料问 `wireless`，没有字面匹配，`results` 是空列表。程序直接结束，不请求模型：

```python
if not results:
    print("知识库没有检索到相关证据；本次不调用模型。")
    return
```

这只能说明“当前方法没有找到”，不能证明知识库一定没有答案。

**情况二：检索到了文字，但文字里没有问题的答案。**

例如问“停车免费吗？”，可能因为“免费”两个字选中了“wifi 免费”。这段资料没有写停车，所以合理回答是“资料不足，无法确定”。

第一种情况由程序直接处理；第二种情况需要模型阅读资料后判断。只检查 `if not results`，不能解决第二种情况。

本课的引用和“不猜测”是给模型的要求，示例没有实现自动核验每个事实。模型仍可能答错或标错来源；带了引用也需要核对原文，后续课程再学习评估。

## 9. 回头看代码：每个变量处在哪一步？

现在重新打开 [rag_baseline.py](rag_baseline.py) 的 `main()`，对照这张表：

| 变量 | 保存什么 | 由谁产生 |
| --- | --- | --- |
| `documents` | 文件名 → 文件全文的字典 | `load_documents()` |
| `chunks` | 全部小段落及其来源 | `split_documents()` |

第一次阅读，沿这五个函数名走一遍就够了。能指出“这一行的输入是什么、返回什么、交给谁”，比背下所有代码更有用。

## 11. 答错时，按这个顺序检查

| 看到的现象 | 先检查哪里 | 本例中的具体检查方式 |
| --- | --- | --- |
| 文件里有资料，程序没有打印出来 | 加载 | 第 1 步是否列出了对应文件？是否已保存文件？ |
| “周末”和时间被分在两块 | 切块 | 第 2 步的原文是否保留了完整含义？ |
| 第一名成了工作日时间 | 检索 | 第 3 步命中了哪些字？正确段落分数是多少？ |
| 选中了周末，但模型输入没有它 | 拼接输入 | 第 4 步的 input 是否包含 hours.md#1 原文？ |
| 输入写着 18:00，模型却说 21:00 | 生成 | 模型是否混用了别的资料或自己的知识？ |
| 有引用，但引用原文没有那个结论 | 生成与核验 | 按引用编号回查该块原文，不能只看引用格式 |

不要只盯着最终回答。沿途的数据能告诉你，错误最早出现在什么位置。

## 12. 扩展：主线学会后再做

原本涉及的工程问题仍然有用，但可以分开学习：

| 扩展问题 | 为什么需要它 | 本课完成了多少 |
| --- | --- | --- |
| 切块长度与重叠 | 避免块太长，或把相邻的关键信息拆散 | 目前只按空行分段；没有长度上限或重叠策略 |
| 加载边界 | 只读取指定范围、大小和格式的资料 | 只读取 knowledge 第一层的 md/txt，跳过链接和隐藏文件，限制大小 |
| 长期稳定的来源编号 | 资料更新后仍能追踪引用 | 目前按文件名和段号编号，未做文档版本管理 |
| 冲突资料 | 两段写着不同时间时不能随意挑一个 | 提示词要求说明冲突；需要两段都被检索并实际提供给模型 |
| 文档里的恶意指令 | 资料可能夹带“忽略规则”等命令 | 提示词区分资料与规则，但提示词本身不能保证防住所有攻击 |
| 离线测试 | 修改代码后能检查加载、排序、空查询等行为 | 本课先用可重复的小实验检查，没有要求你先搭测试框架 |

切块太小时，比如一块只有“周末”，另一块只有“18:00”，单独检索任何一块都可能缺少含义。切块太大时，周末、工作日、预约、费用都混在一起，匹配和阅读都更难。

以后可以比较 300 字无重叠、600 字重叠 80 字、1000 字重叠 120 字。这里的“重叠”是让相邻块共享一段文字，降低信息刚好在边界被切断的影响；这些只是实验参数，字符数也不等于模型 Token 数。

自测：

1. **模型为什么知道周末 18:00 关门？** 因为程序把写着该时间的资料放进了本次请求。
2. **资料已经 print 出来了，模型就能看见吗？** 不能，还要放进实际发出的模型输入。
3. **RAG 必须先安装向量数据库吗？** 不必须，本课用普通文件、列表和关键词检索演示流程。
4. **检索有高分就一定能回答吗？** 不一定，分数只体现本课的字面匹配规则。
5. **正确资料根本没被选中，先改哪里？** 先查看切块和检索；改回答要求不能凭空补回缺失资料。
6. **本课和微调有什么不同？** 本课把资料放进请求，不更新模型参数；微调通过训练更新参数，两者也可以结合使用。
