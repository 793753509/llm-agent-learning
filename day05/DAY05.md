# Day 05：先查原文，再让模型回答

> 今天用四小段自习室资料走完 RAG：读取 → 切块 → 搜索 → 组装输入 → 可选生成。
> 默认只在本地预览，看到资料怎样进入 Prompt；加 --ask-model 才调用生成服务。

## 1. 为什么需要 RAG？

用户问“周末几点关门？”，答案在你电脑的文件里。模型不会因为文件存在就自动读到它，应用需要先找出相关内容，再放进请求。

RAG 是 Retrieval-Augmented Generation，中文叫“检索增强生成”：

```text
程序找资料 → 把问题和资料放进模型输入 → 模型根据资料组织回答
```

例如青禾自习室资料写“周末 18:00 关门”，程序取出它，模型才有依据回答。这里没有训练模型。

## 2. 文件和编号从哪里来？

| 文件或数据 | 来源与用途 |
|---|---|
| [knowledge/hours.md](knowledge/hours.md) | 课程人工编写的营业时间原文 |
| [knowledge/services.md](knowledge/services.md) | 课程人工编写的预约和 wifi 说明 |
| [rag_baseline.py](rag_baseline.py) | 已提供的程序：读文件、找段落、组装请求 |
| `Chunk`、`SearchResult`、Prompt | 程序运行时在内存生成，默认不另存文件 |

本课“知识库”就是这两个文本文件，业务内容全部虚构。
按空行切分后得到四块：

| 程序生成的块编号 | 原文主要内容 |
|---|---|
| `hours.md#1` | 周末 09:00—18:00 开放，18:00 关门 |
| `hours.md#2` | 周一至周五 08:00—21:00 开放，21:00 关门 |
| `services.md#1` | 提前一天预约，每人最多一个座位 |
| `services.md#2` | wifi 免费，连接方式请咨询前台 |

`#1` 是该文件的第一个段落块，不是行号或搜索排名。编号由切块程序生成；插入新段落可能改变后续编号。

## 3. 先运行本地预览

从项目根目录执行：

```bash
uv run python -m day05.rag_baseline "周末几点关门？"
```

输出按五步排列：

```text
[1 加载] 读到两个文件
[2 切块] 得到四个块及编号
[3 检索] 逐块打分，选中 hours.md#1
[4 补充资料] 打印问题、选中原文和来源
[5 生成] 尚未执行
```

这是过程摘要，实际输出还包含每块全文与匹配词。先找到 `18:00` 和 `hours.md#1`。
“打印给你看”与“发送给模型”是两个动作，本次停在预览。

## 4. 资料怎样变成可搜索的块？

从 `main()` 找到前两行流程：

```python
# 源码节选。
documents = load_documents(KNOWLEDGE_DIR)
chunks = split_documents(documents)
```

`documents` 是“文件名 → 全文”的字典；`chunks` 是多个 `Chunk` 的列表。每个 Chunk 保存：

- `text`：这段原文。
- `source`：文件名。
- `index`：该文件中的块序号。
- `id`：文件名和块序号组合的引用编号。

切块是为了只挑需要的段落。今天直接在内存遍历四块，尚未建立单独搜索索引；Day 06 再把表示保存到向量库。

## 5. lexical：本课按相同的词或字找资料

`lexical` 在这里表示**关键词检索**。程序把英文拆成连续单词、中文拆成单字，比较问题与原文共有多少项。这些检索单位不等于模型计费的 Token。

问题“周末几点关门？”拆成六个不重复的字：周、末、几、点、关、门。
周末块命中周、末、关、门，所以分数是 `4÷6≈0.667`；工作日块命中周、关、门，得 `3÷6=0.5`。

```python
# score() 中的核心计算。
query_tokens = tokenize(query)
chunk_tokens = tokenize(chunk.text)
overlap = query_tokens & chunk_tokens
score = len(overlap) / len(query_tokens)
```

`&` 求交集，`len` 数个数；完整函数还处理了空问题。
这个分数只是字面重合比例，不是答案正确的概率。例如 WLAN 和 wifi 没有共同词，程序不会自动把它们当同义表达。

## 6. top-k 决定最多取几块

```bash
uv run python -m day05.rag_baseline "周末几点关门？" --top-k 2
```

`retrieve()` 丢掉零分块，再按分数从高到低排列，最多取前 k 块。
当前问题 k=1 只选周末块；k=2 还选工作日块。即使 k=5，也只有这两块，因为其他块是零分。

“返回更多”不一定更有用：本题只问周末，工作日内容不是必需证据。返回结果 `SearchResult` 同时保留原文和分数，后面需要的是可读原文。

## 7. 把选中的原文放进模型请求

`build_prompt()` 生成的输入类似：

```text
问题：周末几点关门？
参考资料开始：
[来源: hours.md#1]
## 周末开放时间
周末开放时间为 09:00—18:00，18:00 关门。
参考资料结束。
```

另用 `instructions` 要求根据资料回答、资料不足时说明不知道、标注来源。
看懂后，可沿用 Day 03 的配置发起真实请求：

```bash
uv run python -m day05.rag_baseline "周末几点关门？" --ask-model
```

这一步才把问题和选中的原文交给服务，通常是一笔生成请求。预期回答应表达“周末 18:00 关门”，并引用 `hours.md#1`；措辞可能变化。
引用需要核对：编号存在，还要确认对应原文确实支持回答。

## 8. 两种“没有答案”要分开

| 实验输入 | 当前程序可能发生什么 | 应理解为 |
|---|---|---|
| `wireless` | 没有字面匹配，不请求模型 | 当前检索方法没找到，原文可能仍有网络说明 |
| `停车免费吗？` | 因“免费”找到 wifi 块 | 有候选，但原文没有停车答案 |

第二种情况下，合理的模型回答应承认资料不足。仅用 `if not results` 无法覆盖它。
今天没有自动检查生成语义；Day 08 先学习检索评估。

## 9. 真实项目里一般怎么做？

例如内部制度问答，资料通常来自文档系统，由应用读取、切块并保留来源和版本。提问时先按用户可访问范围找相关段落，再带着证据请求模型，最后核对引用与无答案情况。

本课的空行切块和逐块比较适合看懂流程。资料变多时可使用搜索索引，切块也需照顾章节结构与长度；改法是否有效，用固定问题比较。

## 10. 练习与完成标准

1. 用 `wifi 免费吗？` 找到网络原文，再换成 `WLAN 怎么用？`，观察区别。
2. k 从 1 改为 2，最终 Prompt 增加了什么？
3. 资料已在 Python 变量中，哪一步才让生成模型收到？
