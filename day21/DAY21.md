不必开头列十个框架名称。可以这样介绍：

> 青禾自习室助手帮助值班人员查北店预约资料、查看自己的模拟工单，
> 并把人工批准后的草稿写入本地表。提供可观察的检索、MCP 调用和跨进程审批实验。

这句话可以逐项映射到代码和命令。

## 3. 一段好的 README 需要哪些证据？

| 你说的话 | 应提供的可核对证据 |
|---|---|
| 支持检索与来源 | 一个问题、输出来源、对应原文 |
| 真的接了 MCP | client/server 代码、T001 调用结果 |
| 可以恢复审批 | start 后退出，再 approve 的命令 |
| 不会重复写入 | operation_id 唯一约束和验收检查 |
| 会做评估 | 固定题目、规则、通过/失败报告 |
| 知道边界 | 明写固定身份、无真实模型质量评估等限制 |

画图时只画代码里真实存在的箭头。
当前新建的本地工单没有同步到 MCP 静态数据，就不能画成已接通的统一企业工单库。

## 4. 五分钟演示怎样安排？

不用展示所有文件。让每一步回答一个问题：

1. 0:00～0:40：用 E101 问题说明用户需求。
2. 0:40～1:30：运行资料查询，打开被引用的原文。
3. 1:30～2:20：查 T001，再查 T002，说明身份边界。
4. 2:20～3:20：创建草稿、另启进程批准、重复批准。
5. 3:20～4:20：展示 Day 20 报告和 Day 13 故障评估。
6. 4:20～5:00：说两个当前限制和下一步验证计划。

完整命令见 demo.md。演示前先安装依赖和准备环境，避免把下载等待计入五分钟。
需要 API 时另开终端保持服务运行；不要在讲解途中把服务终端当命令终端覆盖。

## 5. 简历上怎样写才准确？

可以基于当前参考版写：

```text
实现青禾自习室助手教学项目，使用 Python 与 LangGraph 串联北店资料检索、
MCP 工单查询和受限计算工具；使用 SQLite 保存显式偏好及待审批草稿，
通过内容摘要与 operation_id 唯一约束控制本地重复写入。
提供 FastAPI、阶段 SSE 和本地集成验收脚本，验证越权拒绝、跨进程恢复及故障轨迹。
```

只有亲手运行向量分支并能解释时，再加“本地 Embedding、Qdrant、RRF 与规则重排”。
只有做过真实模型评估时，再写模型回答指标，并带上样本数量与范围。

不要直接写“生产级”“全自动规划”“准确率提升 30%”“50+ 评估题”。
现有代码没有证明的内容，不能靠简历措辞补出来。
Day 20 的检查项数量也不等于独立自然语言评估题的数量。

## 6. 用具体失败准备三个故事

### 故事一：只找到一条，却误以为找全了

问题：工作日和周末需要两条证据，k=1 只返回一条。
分析：Hit=1 不能代表 Recall=1。
做法：改正指标公式，保留多证据题，比较 k=1/2。
验证：给出 Day 08 的逐题报告，同时说明更大 k 的上下文代价。

### 故事二：工具名称合法，却没有访问权

问题：alice 可以提出 get_ticket(T002)，格式完全正确。
分析：Schema 只管格式，不能确认归属。
做法：身份由执行层提供；工具查 owner；越权统一错误且不带正文。
验证：展示 Day 15 和 Day 20 的拒绝检查，说明演示身份仍不是完整认证。

### 故事三：写入成功后重试，为什么不生成第二张？

问题：动作成功，但完成快照还没记录就中断。
分析：恢复可能再次执行写入节点。
做法：稳定 operation_id、本地数据库唯一约束、摘要核对。
验证：Day 20 重放写入后查表仍一条；说明外部服务需要另外支持幂等。

## 7. 面试回答只用三层

以 checkpoint 为例：

```text
一句话：把流程状态存下来，之后知道从哪里继续。
项目证据：Day 10 把草稿和审批位置保存到本地 SQLite。
边界：恢复不代表所有副作用只执行一次，因此另做 operation_id 防重复。
```

不要只说“checkpoint 是一种持久化机制”，那还是抽象定义。
也不用背完整库文档；把真实数据、函数和一次失败接起来更有说服力。
