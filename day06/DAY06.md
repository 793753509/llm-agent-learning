# Day 06：为什么“无线网络”能找到“wifi”？

> 今天的目标：看见文字怎样变成数字、数字怎样存进本地向量库、检索结果怎样变回原文。

继续使用 Day 05 的虚构“青禾自习室”。今天只替换“查资料”的方法，最后拼接 Prompt 和生成回答仍然复用 Day 05。

学习顺序：先读第 1～4 节，运行不需要新依赖的数字小实验；再按第 5 节运行真实模型和数据库；最后对照第 6～10 节读代码。不要先背接口和公式。

## 1. 从 Day 05 的一个缺点开始

知识库有这样一段：

```text
wifi 免费，连接方式请咨询前台。
```

你问 `wifi`，关键词检索容易找到它。你问 `wireless`，Day 05 的代码找不到：这两个英文单词没有字面重合。

人会联想到它们都与无线网络有关。我们希望检索程序也能利用这种关联，而不只是比较字是否相同。

今天的新流程是：

```text
“无线网络怎么连接？” → Embedding 模型 → 一组数字
“wifi 免费，连接方式请咨询前台。” → 同一个模型 → 另一组数字
                                         ↓
                            比较两组数字是否接近
                                         ↓
                                 返回相关的原文
```

Embedding 模型经过训练，可以把文本转换成适合比较的数字表示。意思相关的文本往往会得到相近的表示，但不能保证每次都找到正确资料。

特别是本课用的是中文模型，`wireless` 这样的英文问题也要实际测试，不能因为换了向量检索就默认一定解决。

## 2. 向量：先当作一个装着数字的列表

下面就是一个二维向量：

```python
vector = [0.8, 0.6]
```

“二维”只是说它有两个数。512 维就是有 512 个数，不需要先想象一个 512 维的空间。

本课真实模型叫 `BAAI/bge-small-zh-v1.5`，每段文本会得到 512 个数。名称中的 `small` 是模型名称的一部分；你先把它当作“这节课使用的文本编码器”即可。[模型说明](https://huggingface.co/BAAI/bge-small-zh-v1.5)

几个容易混淆的地方：

- 一个数不是一个汉字；一段十个字和一段五十个字，都能输出 512 个数。
- 第一个数通常不能直接解释成“网络程度”，第二个数也不能直接解释成“关门程度”。真实向量的表示是训练得到的。
- 向量不是答案。`[0.8, 0.6]` 本身不能告诉用户 wifi 怎么连接。
- 我们使用已经训练好的模型来计算这些数字，没有在训练它。

## 3. 先用两组人工数字，理解“相似度”

暂时假设问题和资料有下面的向量。**这些数字是为了手算而设计的，不是 Embedding 模型的真实输出。**

| 对象 | 人工给定的向量 |
| --- | --- |
| 问题 | `[1.0, 0.0]` |
| 网络资料 | `[0.8, 0.6]` |
| 关门资料 | `[0.0, 1.0]` |

今天用“余弦相似度”比较方向：方向越接近，分数越大。先看这个恰好容易计算的例子：这三个向量的长度都是 1。

```text
问题与网络资料：1 × 0.8 + 0 × 0.6 = 0.8
问题与关门资料：1 × 0   + 0 × 1   = 0
```

所以在这组人工数字里，网络资料排名更靠前。

在项目根目录运行：

```bash
uv run python -m day06.vector_basics
```

你会看到：

```text
网络资料 [0.8, 0.6] -> 余弦分数 0.800
关门资料 [0.0, 1.0] -> 余弦分数 0.000
```

这个实验只需要 Python，没有下载模型，也没有数据库。它让你理解比较过程，不能用来证明一个模型的检索效果。

### 向量长度不是 1 时怎么办？

比如 `[3, 4]` 的长度是 5，将每一项都除以 5，得到 `[0.6, 0.8]`。方向不变，长度变为 1，这叫“归一化”。

[vector_basics.py](vector_basics.py) 的 `normalize()` 做这件事；`cosine()` 先把两个向量归一化，再把对应数字相乘、相加。

余弦分数的理论范围是 -1 到 1。它不是正确率，也不能看到 `0.8` 就断言“答案有 80% 的把握”。不同模型和资料的分数分布不同，后面要用实际问题选择阈值。

**停下来想一下：刚才是模型理解了“网络”，还是我们人为给了网络资料一个接近问题的向量？**

答案是后者。接下来才真正让模型计算向量。

## 4. 向量数据库保存什么？部署在哪里？

你刚才问过向量库在本地还是云端。本课选择的是 **Qdrant local mode，数据库文件保存在你的电脑上**，不用 Docker，也不用启动单独的数据库服务。[Qdrant local mode](https://github.com/qdrant/qdrant-client#local-mode)

把向量库想成一张带有“数字表示”的资料表：

| 资料编号 | 向量（实际有 512 项） | 原文 |
| --- | --- | --- |
| `hours.md#1` | `[0.0012, 0.0737, …]` | 周末 18:00 关门 |
| `services.md#2` | `[-0.0041, 0.0286, …]` | wifi 免费，连接方式请咨询前台 |

这里展示的前两项来自本课的一次实际运行，完整数据以你运行输出为准。原文列为了方便阅读做了缩写。

向量库主要帮我们保存、比较和查找这些记录。它不会仅凭保存原文就自动理解语义；这份代码先调用 Embedding 模型算出向量，再把向量交给数据库。

整套示例的位置是：

| 内容或计算 | 位置 |
| --- | --- |
| 原始资料 | 本机 `day05/knowledge/` |
| Embedding 模型下载缓存 | 本机 `day06/data/models/` |
| 附带的下载缓存 | 默认在本机 `day06/data/huggingface/`；已有 HF_HOME 设置时沿用它 |
| Embedding 计算 | 本机 CPU |
| 向量数据库 | 本机 `day06/data/qdrant/` |
| 最终回答 | 只有加 `--ask-model` 才请求 Day 05 已配置的远程生成模型 |

首次加载 Embedding 模型需要联网下载模型文件。下载模型和“把资料发给远程模型计算”是两件事；这里的文本编码在本地执行。

检查这些事情：

1. 问题的向量也是 512 维。
2. 结果中是否出现 `services.md#2`，它排第几？
3. `input` 中有没有原文“连接方式请咨询前台”？

这道中文问题的关键词检索也可能成功，因为它和资料有“网络、连接”等字面重合。运行它的目的是看懂流程；证明语义检索改善了什么，要继续做第 11 节的对照实验。

## 6. 读代码：文字是在哪一行变成向量的？

先打开 [build_index.py](build_index.py) 的 `main()`。核心流程是：

```python
# 源码节选；完整 imports 在文件顶部。
chunks = split_documents(load_documents(KNOWLEDGE_DIR))
model = load_embedder()
vectors = embed_texts(model, [chunk.text for chunk in chunks])
```

第一行仍然是 Day 05 的加载和切块。第二行加载已经训练好的模型。第三行把全部原文交给模型编码。

`[chunk.text for chunk in chunks]` 的意思是“从每个 chunk 里取出 text，组成一个新列表”，相当于：

```python
texts = []
for chunk in chunks:
    texts.append(chunk.text)
```

四段文字进去，四个向量出来，位置一一对应：

```text
chunks[0].text → vectors[0]
chunks[1].text → vectors[1]
chunks[2].text → vectors[2]
chunks[3].text → vectors[3]
```

再到 [vector_store.py](vector_store.py) 找 `embed_texts()`：真正编码发生在 `model.embed(texts)`。返回的每项是一个数字数组，`.tolist()` 把它转成普通 Python 列表。

这个库返回的是可以逐个取出结果的对象，所以代码使用 `for vector in model.embed(texts)` 收集所有向量。第一遍先把它当作“循环取出每段文字的编码结果”。

## 7. 建库时的三个新名字：collection、point、payload

### collection：装一批记录的容器

本课的 collection 叫 `day06_study_room`，可以类比一张表。创建时声明里面的向量应有多少维、用什么方法比较：

```python
# 源码节选：client 是本地 Qdrant 客户端，models 来自 qdrant_client。
client.create_collection(
    collection_name=COLLECTION,
    vectors_config=models.VectorParams(
        size=512,
        distance=models.Distance.COSINE,
    ),
)
```

`COSINE` 表示使用刚才学到的余弦相似度。高分排在前面。

### point：一条记录

一条记录包含 ID、向量和附带资料。Qdrant 的点 ID 支持整数或 UUID；本课把 `hours.md#1` 转为可重复生成的 UUID 作为数据库 ID，同时在附带资料中保留原来的可读编号。

你给用户引用的仍然是 `hours.md#1`，不必让用户阅读一长串 UUID。

### payload：和向量一起保存的原文与来源

```python
# 结构示意，text 省略了一部分。
payload = {
    "id": "hours.md#1",
    "source": "hours.md",
    "index": 1,
    "text": "## 周末开放时间\n周末开放时间为……",
}
```

代码里的 `asdict(chunk)` 就是把 dataclass 转成这样的字典。

我们用向量查找记录，找到后要取回 `payload["text"]` 给生成模型阅读。只存向量而不保留原文，检索成功后也没有材料可以回答。

最后的 `client.upsert(...)` 把这些记录写入数据库。`upsert` 表示同 ID 已存在就更新，不存在就插入。本课的入口先重建 collection，再批量写入，所以重复运行仍然是当前资料对应的四条记录。

## 8. 查询时为什么还要调用一次 Embedding？

数据库里保存的是资料的向量。现在要比较一个新问题，当然也需要把这个问题转换成向量：

```python
query_vector = embed_query(model, query)
```

**文档和问题必须使用兼容的编码方式。** 最容易保证这一点的做法就是使用同一个模型、相同维度和对应的预处理规则。

本课按照 BGE 的使用建议，只在短问题前加一句检索提示，文档直接编码：

```text
问题编码输入：为这个句子生成表示以用于检索相关文章：无线网络怎么连接？
资料编码输入：## 网络\nwifi 免费，连接方式请咨询前台。
```

这个前缀是编码问题时使用的提示，不会替代用户原问题，也不会当作资料交给生成模型。[BGE 使用说明](https://huggingface.co/BAAI/bge-small-zh-v1.5#usage)

之后调用：

```python
# search_vectors() 中的核心查询。
points = client.query_points(
    collection_name=COLLECTION,
    query=query_vector,
    limit=top_k,
    with_payload=True,
).points
```

- `query`：用这组数字去比较资料向量。
- `limit`：最多返回几条。
- `with_payload=True`：把原文和来源一起取回来。

结果再转换成 Day 05 的 `SearchResult`。因此后面的 `build_prompt(query, results)` 不需要知道我们使用的是关键词还是向量检索。

## 9. “建库”和“查询”为什么分成两个入口？

| 建库：资料变化时执行 | 查询：用户提问时执行 |
| --- | --- |
| 读取全部资料 | 读取当前索引说明，检查资料是否变化 |
| 为全部 chunk 计算向量 | 只为本次问题计算向量 |
| 写入本地数据库 | 搜索已有向量并取出原文 |

本课查询入口为对照实验还会读取这四段原文，**但不会重新计算四段文档的向量**。

如果你有一万段资料，每次提问都重新编码一万段，就重复做了大量不必要的工作。资料没变时复用已保存的向量即可。

`data/index.json` 记录模型名、FastEmbed 版本、维度、问题前缀、切块规则、资料摘要和记录数。资料摘要是根据内容计算的一串校验值；内容变化后它通常也会变化。

查询前会检查这些信息。你修改 Day 05 的资料后，查询入口会提醒重新运行 `day06.build_index`，避免拿新原文和旧向量混在一起。

本课全量重建只替换 `day06_study_room`；先算完新向量，再替换旧记录。重建中断后重新运行即可，入口没有实现生产系统的无中断切换。

## 10. 检索到了结果，也不代表知识库有答案

试问：

```bash
uv run --group rag python -m day06.vector_retriever "火星今天多少度？" --top-k 1
```

它仍可能返回自习室资料中的某一段。原因是：我们问数据库“这里面哪一段最近”，即使全部不相关，也可能有一个相对最近的结果。

可以用 `--min-score` 设置最低余弦分数。例如下面只是**观察过滤行为的实验参数**，不是推荐的通用阈值：

```bash
uv run --group rag python -m day06.vector_retriever "火星今天多少度？" --min-score 0.99
```

观察是否返回空列表。若没有达到条件的结果，程序直接结束，不调用生成模型。

阈值太高可能漏掉正确资料，太低可能留下噪声。没有一个对所有模型、所有知识库都适用的分数。即使超过阈值，最终回答仍需根据原文检查证据是否足够。

## 11. 三个小练习：一次只改一件事

### 练习一：从向量长度开始

打开 `vector_basics.py`，在自己的草稿中打印：

```python
from day06.vector_basics import cosine, normalize

print(normalize([3.0, 4.0]))
# [0.6, 0.8]
print(cosine([1.0, 0.0], [3.0, 4.0]))
# 0.6
```

先手算，再运行。为什么第二项不是 3？因为余弦比较先消除了长度的影响。

### 练习二：对照关键词和向量

分别查询：

```bash
uv run --group rag python -m day06.vector_retriever "wifi" --top-k 1
uv run --group rag python -m day06.vector_retriever "wireless" --top-k 1
uv run --group rag python -m day06.vector_retriever "周末几点关门？" --top-k 1
uv run --group rag python -m day06.vector_retriever "火星今天多少度？" --top-k 1
```

每道问题记录：关键词第一名、向量第一名、原文是否真的包含答案。不要直接比较两种检索器的原始分数大小，它们的计算规则不同。

下面是本课的一次真实运行，方便你核对来源；自己的实验仍然以实际输出为准：

| 问题 | 关键词第一名 | 向量第一名 | 是否有答案 |
| --- | --- | --- | --- |
| wifi | services.md#2 | services.md#2，约 0.575 | 有网络资料 |
| wireless | 没有结果 | services.md#2，约 0.359 | 找到了相关网络资料 |
| 周末几点关门？ | hours.md#1 | hours.md#1，约 0.622 | 有，18:00 |
| 火星今天多少度？ | services.md#1 | services.md#1，约 0.359 | 没有，预约资料无法回答火星温度 |

这里 `wireless` 和火星问题的向量分数四舍五入后都接近 0.359，但一个找到了相关资料，一个没有答案。不能把一个固定分数直接当作“能够回答”的证明。

遇到 `wireless` 仍没选对，就如实记为失败；这能告诉我们中文模型在这道跨语言问题上的实际表现。

### 练习三：修改资料后为什么要重建？

把 Day 05 第一段中的两个 `18:00` 都改成 `17:00`。先查询，预期提示资料已变化；再运行建库入口、重新查询，检查原文是否变成新时间。

完成后恢复两个 `18:00`，再建库一次。重复建库后的记录数应仍为 4。

改动前后，问题中的“周末”和“关门”不变，但文档向量与原文都需要对应到同一版资料。
