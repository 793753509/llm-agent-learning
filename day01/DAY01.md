# Day 01：发出第一次模型请求，看清输入和输出

> 今天做一个命令行学习助手：输入技术主题，拿到解释、例子和自测题。
> 先认识一次请求；调用真实模型需要你自己的服务配置和额度。

## 1. 这个程序解决什么问题？

假设你想学“Python 列表”，每次都希望得到定义、例子和练习。程序把这个固定要求写成提示词，你只输入主题即可。

```text
你输入主题 → Python 组装要求 → 模型服务生成文字 → Python 打印回答和用量
```

模型运行在配置的服务端；本地 Python 负责收集输入、发送请求和展示结果。今天没有工具调用、知识库或多轮记忆。

## 2. 先认清文件和数据从哪里来

| 内容 | 来源与用途 |
|---|---|
| [hello_llm.py](hello_llm.py) | 随课程提供的参考程序，提示词也写在这里 |

## 3. 运行一次

所有命令从项目根目录执行，也就是有 `pyproject.toml` 的目录。环境准备见 [总说明](../README.md)。

```bash
uv sync --locked
uv run python -m day01.hello_llm --help
```

`--help` 只显示用法，不请求模型。真实运行前，配置 `DASHSCOPE_API_KEY` 或 `ALIYUN_API_KEY`；也可由你在项目根目录的 `aliyun_api_key` 文件中保存密钥，该文件已被 Git 忽略。

`LLM_BASE_URL` 指定服务地址，`LLM_MODEL` 指定模型名。当前默认值是本项目原有的阿里云配置，不保证其他账号可以直接使用；换服务时按你的账号同步配置地址、模型和 Key。代码使用 OpenAI Python SDK，但请求发往 `BASE_URL` 指定的服务。

```bash
uv run python -m day01.hello_llm "Python 列表" --simple
uv run python -m day01.hello_llm "Python 列表" --interview
```

第一条偏向初学者，第二条增加面试练习；每条都会发起真实请求。两个模式不能同时使用。

你应看到主题讲解以及末尾的模型名、输入/输出 Token。具体措辞和用量会变化，不需要与某份示例逐字一致。

## 4. 一次请求的几个字段

在 `ask_llm()` 中找到这段源码：

```python
response = client.responses.create(
    model=MODEL,
    instructions=build_instructions(simple, interview),
    input=f"请讲解这个技术主题：{topic}",
)
```

| 字段 | 本课含义 |
|---|---|
| `client` | 与模型服务通信的客户端；创建它还没有生成回答 |
| `model` | 请求哪个模型 |
| `instructions` | 固定的回答要求，例如用中文、给出例子 |
| `input` | 这次的主题 |
| `response.output_text` | 服务生成的回答文字 |
| `response.usage` | 服务返回的用量；有些兼容服务可能不提供 |

Prompt 就是给模型的提示内容，本课由固定要求与本次主题组成。修改提示词会改变本次输入，不会训练模型。

Token 是模型处理文本的计量单位，不等于字符数，也不保证一个汉字恰好对应一个 Token。输入和输出分别计数；服务未返回时显示“服务商未返回”，不能据此当作零消耗。

本课每次只传当前主题，第二次运行不会自动记住第一次。Day 04 再学习如何提供历史。

## 5. 改一处，观察它为什么变化

先打开 `build_instructions()`：它把基础要求与所选模式拼接起来。尝试在 `SIMPLE_INSTRUCTIONS` 中加一句“代码示例最多五行”，重新运行同一主题。

观察：回答是否遵守？有没有为了缩短代码漏掉关键条件？提示词是要求，仍需检查实际回答。

一个好的小实验只改一处。不要同时换模型、换问题、换提示词，否则很难解释结果为什么变了。

## 6. 顺着函数读代码

```text
main：收集参数
  → create_client：读取配置并创建客户端
  → ask_llm：发请求，整理成 StudyResult
  → display_result：展示回答与用量
```

`StudyResult` 是我们自己定义的数据类，用来把相关字段放在一起。它既不是模型，也不是输出文件。

`print_api_error()` 把认证失败、网络问题、超时等异常变成短提示。服务返回成功但文字为空，也会报错。
客户端设了 30 秒超时并允许有限重试；包含重试的整个命令可能超过 30 秒。

## 7. 真实项目里一般怎么做？

例如企业学习助手，会把“解释方式”写成可维护的提示模板，把用户输入交给后端请求模型，再检查结果并显示。配置由运行环境提供，回答质量用一组固定问题反复核对。

本课先在终端完成这条链。以后增加网页或数据库，核心仍然是“明确输入 → 请求 → 处理输出与失败”。工具、资料和历史都需要应用另外接入。

接口字段可按需查 [Responses API](https://developers.openai.com/api/reference/python/resources/responses)；兼容服务的能力以它实际支持的接口为准。

## 8. 自测与完成标准

1. `instructions` 和 `input` 分别是谁提供的？
2. Python 已经读到一个文件，模型是否就能看到？
3. 用量没有返回，能否说本次免费？

<details>
<summary>参考答案</summary>

1. 前者由程序预先定义，后者来自本次主题；两者一起构成请求内容。
2. 不能，应用需要把选定内容放进请求。
3. 不能，缺失统计不代表零用量或免费。

</details>
