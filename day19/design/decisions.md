# 三张取舍卡片

这些是参考实现的人工取舍记录。修改实现后，同时更新对应选择与代价。

## 1. 默认先预览资料

问题：初学者难以分辨错误来自检索还是生成。
选择：默认返回候选原文和来源；生成使用显式 --ask-model。
收益：每一步可观察，默认不消耗模型 API。
代价：原文不一定直接回答问题，需要核对；没有完整自然语言回答体验。

## 2. 只给写入单独持久化审批

问题：同一草稿重启后仍应可审批，重复批准不应重复写入。
选择：复用 Day 11 的 SQLite checkpoint、内容摘要、operation_id 唯一表。
收益：能演示真实跨进程恢复和本地幂等。
代价：单用户串行实验；外部工单一致性、并发审批、认证还未实现。

## 3. 有限规则先把线路接通

问题：同时调试模型决策、MCP、检索和 API 很难定位问题。
选择：查工单/计算采用明确输入格式，其他问题走资料检索。
收益：能用固定样例验证具体组件是否协作成功。
代价：不理解任意自然语言意图；不能据此声称自主规划能力。后续替换 route 节点时保持执行入口和评估不变。
